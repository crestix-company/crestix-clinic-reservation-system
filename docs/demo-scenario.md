# デモシナリオ

先方クリニックへ画面を見せる際の推奨デモ順序です。
「予約が一元管理されたらこうなる」という完成イメージが伝わる順番になっています。

## 1. ダッシュボード (`/admin`)

まず管理画面トップを開き、「本日の予約」「当日診察」「検査予約」「待機中」の4つのKPIが
ひと目で分かることを見せる。すべてのチャネル（LINE・Web・電子カルテ・院内受付・Google）からの
予約が1つの画面に集約されていることを伝える。

## 2. 予約内容別

ダッシュボード中段の「予約内容別」チャートで、一般診察・胃カメラ・大腸関連・人間ドックの
件数比率が一目で分かることを見せる。

## 3. 予約経路別

同じく「予約経路別」で、どのチャネルからの予約が多いか（Web・LINE・電子カルテ・院内受付・Google）を
ドーナツチャートで確認。マーケティング・導線改善の判断材料になることを伝える。

## 4. 予約一覧 (`/admin/reservations`)

検索・絞り込み（予約内容・経路・状態・日付）を実演し、全予約データへの横断的なアクセスができることを見せる。

## 5. カレンダー (`/admin/calendar`)

日表示・週表示を切り替え、時間帯ごとの埋まり具合を確認。予約種別フィルタで
胃カメラ・大腸関連等の検査予約だけを絞り込める点を見せる。

## 6. 当日受付 (`/admin/reception`)

「呼出」→「診察開始」→「完了」のボタンを実際に押し、受付番号の状態がリアルタイムに変わる様子を見せる。
受付スタッフの日々の運用がこの1画面で完結することを伝える。

## 7. 患者向けWeb予約 (`/reserve`)

スマートフォン幅で開き、予約内容選択 → 日付選択 → 時間選択 → 患者情報入力 → 確認 → 完了まで
実際に操作してもらう。患者側の予約がそのまま管理画面に反映される設計であることを説明する。

## 8. 院内モニター (`/display`)

待合室モニター想定のフルスクリーン画面を見せ、現在の呼出番号・待ち人数が
遠くからでも見やすい表示になっていることを伝える。

---

補足として `/admin/analytics`（集計）を見せると、「一元化するとここまで分かる」という
将来の分析価値（予約内容 × 予約経路のマトリクス等）を訴求できます。
